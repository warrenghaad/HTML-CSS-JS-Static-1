## 2) What “aliases” should mean (so Codex doesn’t improvise)

On macOS, the cleanest is:

### Option A (best): **symlinks** in `_aliases/`

- `_aliases/pilot/…` symlinks that mirror the old pilot structure, pointing to the new home in `content/…`
    

### Option B (Obsidian-friendly fallback): **alias stub markdown files**

If symlinks cause Obsidian weirdness, use stub `.md` files like:

```md
# Alias
This file moved.

- Original: /path/to/pilot/lesson-01.md
- New: /Users/.../CurriculumStudioApp/content/mesopotamia/lessons/lesson-01.md

Open the new file here: [[content/mesopotamia/lessons/lesson-01]]
```

Codex should implement **A**, and fall back to **B** if needed.

## 4) One important caution (Obsidian + app repo)

Obsidian will index everything. If you keep `node_modules` inside the vault, Obsidian can slow down.

Two safe approaches:

- Keep `node_modules` outside via workspace tricks (harder), OR
    
- Keep it inside but **ignore** it (easy)
    

Codex should:

- add `node_modules/` to `.gitignore`
    
- and you should add it to Obsidian “Files & Links → Excluded files” (Codex can remind you)
