Kanban Board

The Kanban board provides a visual representation of your workflow, helping teams manage work in progress and optimize flow.

Board Columns

Default columns in your Kanban board:

Backlog

Tasks waiting to be started

To Do

Ready for work

In Progress

Currently being worked on

Review

Awaiting approval

Done

Completed tasks

Card Features

Feature Description
Title & Description Add a clear title and detailed description to each card
Labels Color-coded labels for categorization (Bug, Feature, Enhancement)
Assignees Assign one or more team members to a card
Due Dates Set deadlines and receive reminders
Checklists Break down tasks into subtasks with checkboxes
Attachments Add files, images, or links to cards
Comments Discuss work directly on the card

WIP Limits

Work In Progress (WIP) Limits

Set maximum cards per column to prevent bottlenecks and maintain flow. When a column reaches its limit, it highlights in red to signal the team.

Scrum Framework

The Scrum framework enables iterative development through time-boxed sprints, defined roles, and regular ceremonies.

Scrum Roles

Product Owner

  • Manages the product backlog
  • Defines user stories and priorities
  • Represents stakeholder interests
  • Accepts or rejects completed work

Scrum Master

  • Facilitates Scrum ceremonies
  • Removes team impediments
  • Coaches the team on Scrum practices
  • Shields team from distractions

Development Team

  • Self-organizing and cross-functional
  • Delivers potentially shippable increments
  • Estimates work effort
  • Commits to sprint goals

Scrum Events

Event Duration Purpose
Sprint Planning 2-4 hours Define sprint goal and select backlog items
Daily Standup 15 minutes Sync team progress and identify blockers
Sprint Review 1-2 hours Demo completed work to stakeholders
Retrospective 1-2 hours Reflect on process and identify improvements

Product Backlog

The product backlog is an ordered list of everything that might be needed in the product.

User Story Format

As a [type of user]

I want [goal/desire]

So that [benefit/value]

Story Points

Estimate effort using the Fibonacci sequence:

1 2 3 5 8 13 21

Higher numbers indicate more complexity and uncertainty.

Backlog Prioritization

Priority Label Description
P0 Critical Must be done immediately, blocking issues
P1 High Important for next release
P2 Medium Should be done when time permits
P3 Low Nice to have, future consideration

Sprint Planning

Plan and manage time-boxed iterations to deliver incremental value.

Sprint Configuration

Sprint Duration 1-4 weeks (default: 2 weeks)
Sprint Goal One clear objective for the sprint
Team Velocity Average story points completed per sprint
Capacity Available team hours minus holidays/meetings

Sprint Workflow

1

Planning

Select items from backlog based on priority and capacity

2

Execution

Team works on sprint items, daily standups for sync

3

Review

Demo completed work, gather feedback

4

Retrospective

Reflect on what went well and what to improve

Reports & Metrics

Track team performance and project progress with built-in reporting tools.

Available Reports

Burndown Chart

Shows remaining work in a sprint over time. The ideal line slopes downward to zero by sprint end.

Velocity Chart

Displays story points completed across sprints to predict future capacity.

Cumulative Flow

Visualizes work items in each status over time, helps identify bottlenecks.

Cycle Time

Measures average time from work started to completed.

Key Metrics

Metric What It Measures Good Indicator
Velocity Story points per sprint Consistent or improving
Lead Time Request to delivery Decreasing over time
Cycle Time Start to completion Short and predictable
Throughput Items completed per week Steady or increasing
Sprint Burndown Work remaining in sprint Tracks close to ideal line
